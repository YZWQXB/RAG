## 二、v1.0 回顾（昨天）

1. **多租户骨架**：JWT → 仓储过滤 → RLS → 对象存储前缀，四道防线；应用连接使用 `NOBYPASSRLS` 角色。
2. **可靠入库**：outbox 表保证「上传成功即最终一致」，worker 轮询 + 卡住任务自愈 + 指数退避。
3. **检索管线**：pgvector 余弦 + pg_trgm 三元组，RRF 融合，可选重排，token 预算内组装上下文。
4. **流式问答**：SSE 心跳防代理断流，引用上标映射真实分块页码。
5. **真实模型接入**：本机 bge-m3（ModelScope 下载、启动预热、线程池推理）+ 讯飞星辰 MaaS 生成。
6. **阈值标定**：bge-m3 实测可答 p50=0.742 / 不可答 max=0.513 → 阈值定为 0.55；958 个历史分块用新模型重建向量。
7. **模式切换器**：右上角徽标，点击切换在线/离线，改内存 + 写 `.env` + 清查询缓存，worker 按 mtime 跟随。
8. **缺陷修复**：假 LLM 硬编码同一句回答 → 改为从上下文派生。

### C. 离线可用性（今天最大的返工）

用户反馈「离线还是拒答」，实测确认上一版修复无效，重新定位为**向量空间不匹配**：

```
库中分块向量：bge-m3         查询向量：字符袋(fake)
余弦 ≈ 0.05（无意义）  →  阈值降到 0 也没用
```

最终方案：**离线不碰向量**，新增 `lexical.py` 逐块比对文本，打分 = 字符袋余弦 × 查询覆盖率。

## 四、技术难点与解法

| # | 现象 | 根因 | 解法 | 验证 |
|---|---|---|---|---|
| 1 | 离线问什么都说「资料未涵盖」 | 分块是 bge-m3 向量、查询是字符袋向量，两个空间无关，余弦恒 0.05；pg_trgm 对中文又几乎为 0（需连续三字重合） | 离线改为词法打分（余弦 × 覆盖率），彻底不读向量列 | 958 块真实语料：4/4 作答、2/2 拒答 |
| 2 | 换嵌入模型后「没资料也硬答」 | 0.35 阈值是给假向量标定的，bge-m3 分布整体抬高 | `calibrate_threshold` 重标为 0.55，并为 fake 单独设 0.10 | 分离准确率 100% |
| 3 | 点「停止」后刷新，回答消失 | 客户端断开抛 `CancelledError`（BaseException），原代码只捕获 `LLMError` | 捕获 `CancelledError/GeneratorExit` + `asyncio.shield` 落库为 `incomplete` | 关闭生成器后库中存在 incomplete 消息 |
| 4 | 十几个并发问答就开始排队 | 向量推理（1~2 秒）在数据库事务内执行，独占连接池一条连接（共 15 条） | `_prepare` 拆两个短事务，embedding 移到事务外 | 全量回归 + 事务只含 DB 操作 |
| 5 | 中文 `**加粗：**正文` 显示成字面星号 | CommonMark 的 right-flanking 规则：闭合符前是中文标点、后是汉字，不构成强调 | 引入 `remark-cjk-friendly` | 真实分块 SSR：加粗已渲染、无裸 `**` |
| 6 | 引用弹窗里 Markdown 不渲染 | 弹窗用 `<pre>` 直接输出纯文本 | 复用 `Markdown` 组件，渲染前剥离分块头部与空标记行 | SSR 断言 + 构建通过 |
| 7 | 页面每次渲染都多出两行注释文字 | 注释写在 JSX 返回体里，`//` 被当成文本节点 | 移到组件外做块注释 | 渲染输出无注释文本 |
| 8 | 测试偶发失败（`assert 'fake' != 'fake'`） | `settings` 是进程级单例，前序用例已改过 provider，该用例依赖隐式基线 | 显式 `monkeypatch` 基线值 | 单文件 15 项稳定通过 |
| 9 | 客户端单测 MockTransport 失效 | Provider 改用进程级共享 httpx 客户端后，patch 构造器不再生效 | 直接替换 `app.core.http._client` | 13 项 Provider 用例通过 |
| 10 | `uv sync` 报「拒绝访问」 | API 进程占用了 venv 里的 .pyd 文件 | 先停服务再同步 | 依赖安装成功 |
